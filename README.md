# othello-rl

A reinforcement learning agent for the board game Othello: a CS 401R final project.

**Question:** does training against a pool of past checkpoints produce stronger, more stable agents than naive latest-vs-latest self-play, and does self-play win rate reveal the difference?

The experiment is a 2×2 design on 4×4 and 6×6 boards:

| | `naive` (latest vs latest) | `pool` (past checkpoints) |
|---|---|---|
| **`env`** targets (opponent-as-environment) | env-naive | env-pool |
| **`negamax`** targets | negamax-naive | negamax-pool |

Agents are scored against random/greedy/positional players and exact solvers, and with a MADRID-style checkpoint-regret analysis. A web demo lets visitors play training snapshots. The full plan and timeline are in [docs/spec.md](docs/spec.md).

## Setup

```bash
make setup          # uv venv (Python 3.12) + pip install -e ".[dev]" + npm install in web/
```

Without `uv` (e.g. on the training server): `python3 -m venv .venv && .venv/bin/pip install -e ".[dev]"`. On a GPU server, install the matching torch build first (see pytorch.org).

## Commands

| Command | What it does |
|---|---|
| `make test` | pytest + web typecheck and tests. Tests that hit an unimplemented stub are reported as `skipped: TODO <function>` |
| `make data` | Build the fixed benchmarks in `data/` (see [data/README.md](data/README.md)) |
| `make sweep-4x4 JOBS=8` | E1: all four conditions × 5 seeds on 4×4 |
| `make pilot-6x6`, `make sweep-6x6` | P and E2 on 6×6 |
| `make sync SERVER=user@host` | rsync `runs/` back from the training server |
| `make figures` | `runs/` → `figures/`, `tables/` |
| `make demo RUN=runs/e2-6x6/env-pool/seed0` | Export a run for the web demo |
| `make web-dev` | Serve the demo locally |

A single run:

```bash
.venv/bin/python -m othello_rl.train --config configs/4x4.yaml --exp dev --target env --sampling naive --seed 0
```

Every config field is also a flag (`--games 2000`, `--lr 1e-4`, ...). Output goes to `runs/<exp>/<target>-<sampling>/seed<k>/`.

## Layout

```
src/othello_rl/   engine · players · solver · nets · replay · targets · selfplay · pool · train
                  evaluate · regret · export · config · rundir
configs/          4x4.yaml, 6x6.yaml (target/sampling/seed come from the CLI)
data/             fixed benchmark positions (committed)
scripts/          build_data · sweep · analyze · export_demo
tests/            pytest suite
runs/             training output (gitignored)
figures/ tables/  generated by scripts/analyze.py
web/              Vite + TypeScript demo (onnxruntime-web)
docs/             proposal and spec
```

Two rules keep the comparison honest: `target` is only read in `selfplay.py` and `targets.py`, and `sampling` is only read in `pool.py`.
